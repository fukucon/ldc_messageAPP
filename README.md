# AIチャットボット (GAS + Gemini)

社内規程をスプレッドシートに登録しておき、社員が質問すると規程の内容に基づいて
Gemini が回答するチャットボットです。分野（カテゴリ）ごとに参照シートを分けられます。

## 画面構成

| URL | 画面 |
| --- | --- |
| （パラメータなし） | メニュー画面（トップページ） |
| `?app=bot&cat=<id>` | 分野別チャット画面 |
| `?app=settings` | 設定画面（パスワード必須） |

## 用語：分野とカテゴリ

2階層で管理します。

- **分野**（固定）… 労務系・経理系・購買系。メニューの選択肢で、規程シートに対応します。
  `setup.gs` の `AREAS` で定義します。
- **カテゴリ**（自由）… トラブル・請求・休暇など、追加ルールを分類する小分類。
  設定画面のプルダウンから選ぶか、その場で新規追加できます。

| 分野ID | 分野 | 参照シート | ID接頭辞 |
| --- | --- | --- | --- |
| `roumu` | 労務系 | 就労規則 | `R` |
| `keiri` | 経理系 | 経理規程 | `K` |
| `kobai` | 購買系 | 購買規程 | `B` |

## セットアップ手順

1. スプレッドシートに紐づくApps Scriptプロジェクトに各ファイルをコピー。
2. `setupApiKey()` の `API_KEY` に Gemini API キーを貼り付けて1回実行。
   実行後は `API_KEY` をプレースホルダに戻してよい（キーはスクリプトプロパティに残る）。
3. `setupBot()` を1回実行し、各シートを生成。
4. 「就労規則」「経理規程」「購買規程」の各シートのA2以降に規程本文を貼り付け。
5. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で公開。
6. 発行されたURLを開くとメニュー画面が表示される。

## 回答の仕組み

質問のたびに、以下をまとめて Gemini（gemini-2.5-flash）へ送ります。

```
基本指示（BOT_SYSTEM_INSTRUCTION）
===== 規程ここから =====
（分野の規程シート本文）
トラブル：ハラスメント相談は人事へ直接連絡する。[R1]   ← 追加ルール（設定画面から書き出し）
休暇：有給申請は3営業日前まで。[R2]
===== 規程ここまで =====
【社員からの質問】
```

規程に書かれていない事項は「記載がありません」と答えるよう指示しています。

## 設定画面（追加ルール）

パスワード（`code.gs` の `SETTINGS_PASSWORD`、初期値 `ldcpass`）で保護されています。
照合はサーバー側で行うため、パスワードは画面のソースには出ません。

**追加ルール** を1行ずつ登録します。1件につき3つを入力します。

1. **分野** … 固定のプルダウン（労務系／経理系／購買系）
2. **カテゴリ** … 既存から選択、または「＋ 新しいカテゴリ…」でその場で追加
3. **追加ルール** … 本文（1行）

保存すると：

1. 「設定」シートに `[ID, 分野, カテゴリ, 追加ルール]` として記録される
2. **分野に対応する規程シートの末尾のA列**へ `カテゴリ：ルール本文[ID]` の形で1行ずつ書き出される

AIは設定シートを読まず、**規程シートだけ**を読みます（追加ルールはその末尾に入っています）。

IDは分野ごとに自動採番されます（`R1`, `K1`, `B1` …）。削除した番号は再利用されません。`ADMIN_EMAILS` にメールアドレスを列挙すると、保存できる人を限定できます（空なら制限なし）。

## データ構造（スプレッドシート）

- **就労規則 / 経理規程 / 購買規程**: A2以降に規程本文（1行目は説明）。末尾に追加ルールが自動追記される
- **質問ログ**: `日時`, `分野`, `社員`, `質問`, `回答`
- **設定**: `ID`, `分野`, `カテゴリ`, `追加ルール`（1行 = 1ルール）
