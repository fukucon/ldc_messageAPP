# AIチャットボット (GAS + Gemini)

社内規程をスプレッドシートに登録しておき、社員が質問すると規程の内容に基づいて
Gemini が回答するチャットボットです。分野（カテゴリ）ごとに参照シートを分けられます。

## 画面構成

| URL | 画面 |
| --- | --- |
| （パラメータなし） | メニュー画面（トップページ） |
| `?app=bot&cat=<id>` | カテゴリ別チャット画面 |
| `?app=settings` | 設定画面（パスワード必須） |

## カテゴリ（シリーズ）

| ID | 名前 | 参照シート |
| --- | --- | --- |
| `roumu` | 労務系 | 就労規則 |
| `keiri` | 経理系 | 経理規程 |
| `kobai` | 購買系 | 購買規程 |

カテゴリは `setup.gs` の `CATEGORIES` に1件足すだけで、
メニュー・チャット画面・設定画面すべてに自動で反映されます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `code.gs` | メイン動作（画面振り分け・回答生成・履歴・設定） |
| `setup.gs` | カテゴリ定義とシート生成 |
| `index.html` | メニュー画面（トップページ） |
| `bot.html` | カテゴリ別チャット画面 |
| `settings.html` | 設定画面 |
| `appsscript.json` | マニフェスト（Webアプリ設定） |
| `OCR.md` | 退避：PDF/画像OCR機能のコード |
| `CHAT.md` | 退避：旧Googleチャット風アプリのコード |

## セットアップ手順

1. スプレッドシートに紐づくApps Scriptプロジェクトに各ファイルをコピー。
2. `setupApiKey()` の `API_KEY` に Gemini API キーを貼り付けて1回実行。
   実行後は `API_KEY` をプレースホルダに戻してよい（キーはスクリプトプロパティに残る）。
3. `setupBot()` を1回実行し、各シートを生成。
4. 「就労規則」「経理規程」「購買規程」の各シートのA2以降に規程本文を貼り付け。
5. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で公開。
6. 発行されたURLを開くとメニュー画面が表示される。

## 回答の仕組み

質問のたびに、以下をまとめて Gemini（gemini-2.5-flash）へ送ります。

```
基本指示（BOT_SYSTEM_INSTRUCTION）
===== 規程ここから =====
（カテゴリの規程シート本文）
労務系：在宅勤務は週2日まで。[R1]      ← 追加ルール（設定画面から書き出し）
===== 規程ここまで =====
【社員からの質問】
```

規程に書かれていない事項は「記載がありません」と答えるよう指示しています。

## 設定画面（追加ルール）

パスワード（`code.gs` の `SETTINGS_PASSWORD`、初期値 `ldcpass`）で保護されています。
照合はサーバー側で行うため、パスワードは画面のソースには出ません。

カテゴリごとに **追加ルール** を1行ずつ登録します。保存すると：

1. 「設定」シートに `[ID, カテゴリ, 追加ルール]` として記録される
2. **各規程シートの末尾のA列**へ `カテゴリ名：ルール本文[ID]` の形で1行ずつ書き出される

AIは設定シートを読まず、**規程シートだけ**を読みます（追加ルールはその末尾に入っています）。

IDはカテゴリごとに自動採番されます。

| カテゴリ | 参照シート | IDの形 |
| --- | --- | --- |
| 労務系 | 就労規則 | `R1`, `R2` … |
| 経理系 | 経理規程 | `K1`, `K2` … |
| 購買系 | 購買規程 | `B1`, `B2` … |

削除した番号は再利用されません。`ADMIN_EMAILS` にメールアドレスを列挙すると、保存できる人を限定できます（空なら制限なし）。

## データ構造（スプレッドシート）

- **就労規則 / 経理規程 / 購買規程**: A2以降に規程本文（1行目は説明）。末尾に追加ルールが自動追記される
- **質問ログ**: `日時`, `カテゴリ`, `社員`, `質問`, `回答`
- **設定**: `ID`, `カテゴリ`, `追加ルール`（1行 = 1ルール）
